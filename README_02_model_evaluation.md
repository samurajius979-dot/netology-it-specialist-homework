# Задание «Практика оценки модели» (кредитный скоринг)

Модуль «Машинное обучение и нейросети», программа «Специалист по искусственному интеллекту».

**Файл:** `02_Model_evaluation_solution.ipynb` — заполненный и исполненный шаблон
`Model_evaluation_student_template.ipynb`.

## Задача

В роли ML-инженера банка оценить качество трёх моделей кредитного скоринга, выявить проблемы (дисбаланс классов,
утечка данных, переобучение) и дать рекомендацию о запуске в продакшн.

| Часть | Что сделано |
|-------|-------------|
| 1. Загрузка данных и баланс классов | Подсчёт количества и долей классов, bar plot, оценка соотношения 1 : 5.4 |
| 2. Расчёт метрик | Accuracy, Precision, Recall, F1, ROC-AUC для трёх моделей + сводная таблица; обоснование выбора метрик |
| 3. Визуализация | Confusion matrix (1×3) + ROC-кривые на одном графике + письменная интерпретация |
| 4. Диагностика | Дисбаланс (сравнение с `class_weight='balanced'`), утечка данных (Модель B), кривые обучения Модели C |
| 5. Заключение | Сводная таблица проблем, рекомендация, ограничения |

## Результаты (тестовая выборка, 1250 наблюдений, 195 дефолтов)

| Модель | Accuracy | Precision | Recall | F1 | ROC-AUC | TN | FP | FN | TP |
|--------|----------|-----------|--------|----|---------|----|----|----|----|
| A — Logistic Regression | 0.910 | 0.928 | **0.462** | 0.616 | 0.8235 | 1048 | 7 | 105 | 90 |
| B — Random Forest | 1.000 | 1.000 | 1.000 | 1.000 | 1.0000 | 1055 | 0 | 0 | 195 |
| C — Gradient Boosting | 0.964 | 0.963 | 0.800 | 0.874 | 0.9589 | 1049 | 6 | 39 | 156 |

## Главные выводы

1. **Модель B (Random Forest) — утечка данных.** Она обучена на `model_b.fit(X, y)`, то есть на всём датасете,
   включая test. Отсюда «идеальные» метрики 1.0000 и нулевой разрыв train → test. В продакшн такую модель
   выкатывать нельзя: на новых данных её качество упадёт до уровня логистической регрессии, а офлайн-оценка
   окажется завышенной в разы.
2. **Модель A — смещение к majority-классу.** Accuracy 0.910 выглядит лучше, чем у «константного»
   классификатора (0.844), но Recall по дефолтам всего 0.462: пропущено 105 из 195 дефолтов, а доля
   предсказанных дефолтов 0.078 против реальной 0.156.
3. **Модель C — переобучение.** `n_estimators=500, max_depth=10, learning_rate=0.5, min_samples_leaf=1` на
   5000 наблюдениях: train ROC-AUC = 1.0000 против val 0.9627 (gap 0.0373), валидационная кривая обучения выходит
   на плато. Нужна регуляризация (max_depth 3–4, learning_rate 0.05–0.1, min_samples_leaf 10–20, subsample).
4. **Рекомендация:** ни одна модель не готова к продакшну «как есть». Переобучить B честно, отрегулировать C,
   оставить A как интерпретируемый baseline с `class_weight='balanced'`; целевая метрика — Recall по классу
   «дефолт», порог подбирается под требование Precision ≥ 0.5–0.6.

```bash
jupyter lab 02_Model_evaluation_solution.ipynb
```

полностью воспроизводим без внешних файлов.
